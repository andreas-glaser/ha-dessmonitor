## Important limits

- This qualifies one schedule field in the named installation. It does not
  qualify the other three schedule IDs or the calendar write path.
- A clock read succeeded, and the owner confirmed that the displayed local time
  was already correct. No artificial time shift or candidate calendar write was
  made. Clock serialization has automated coverage, not a new hardware-write result.
- At one observation after the restoration error, the HA editor still displayed
  its previously accepted16:01. Independent API/display/native reads established
  the actual restored16:00; the editor state was not used as restoration proof.
  Its correction on a later cloud refresh was not checked before disabling the
  test integration. This is consistent with preserving a last-known value on a
  failed service call, but is a user-visible limitation worth retaining.
- The first failed independent read and failed restoration response are retained
  in the evidence. An API error is not proof that a command was never applied.
- Raw account/device identifiers, authentication, signed URLs and private
  deployment checkpoints are excluded. Source hashes allow the owner to audit
  the retained originals; they do not independently authenticate a physical
  experiment for a reviewer who does not have those originals.
